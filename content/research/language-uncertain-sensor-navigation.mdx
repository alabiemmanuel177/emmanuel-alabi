## The question

Most instruction-following treats the instruction as ground truth: the robot is
told to turn left at the fire extinguisher, so it looks for a fire extinguisher
and turns left. The failure mode is obvious once stated — if there is no fire
extinguisher, or there are two, or the speaker misremembered, the instruction is
wrong and the system has no representation for that.

This study takes the other position. **An instruction is an observation, not a
command.** It carries information about where to go, it is generated by a
fallible process, and it should therefore enter the system with a confidence
attached and be weighed against what the robot actually sees.

That reframing is the thread back to the rest of this work: Research 1 asked
whether calibrated perceptual uncertainty should change navigation, Research 2
asks whether failure can be anticipated, and this asks where else uncertainty
enters the system. The answer it tests is: the instruction itself.

## Design

**The decision set is the contribution.** Rather than forcing a commit, the
policy can *inspect*, *ignore*, *commit*, or *abstain*, each behind an explicit
route guard. Abstention is a first-class outcome — a robot that declines to act
on an instruction it cannot ground is behaving correctly, and a benchmark that
cannot express that will score it as a failure.

**Benchmark.** Twenty base routes across twelve map identifiers aligned with the
Research 1 platform, three protected paraphrases per route, eight instruction
conditions, exact edit and environment manifests, and explicit annotations for
ambiguous grounding. Deployed variants and evaluator-only fields are kept in
separate namespaces, with evaluator-only fields denylisted from deployed inputs
and that separation covered by regression tests.

**Method.** Deterministic parsing of movement, landmark, turn, topology and
terminal clauses; top-K semantic grounding with a language-only predicted
hypothesis; capped log-odds evidence updates with per-clause reliability. Five
system variants share one deployable input contract.

**Safety boundary.** Nav2 remains the sole owner of path feasibility, collision
checking and motion. The language layer influences where the robot tries to go;
it cannot override what the navigation stack considers safe.

## Evidence discipline

Campaign outputs are create-once: every record carries a checksum, each complete
file has a sidecar SHA-256, and rerunning against an existing path is rejected
rather than silently overwriting. Summaries always report completion and
critical-failure rates together, so a run cannot be described as successful
without also stating how it failed.

The same typed boundaries are implemented across graph-world, ROS-message,
rosbag-replay, Nav2 and failure-monitor adapters, which is what lets a result
obtained in the deterministic graph world be compared against one obtained in
simulation without changing the system under test.

## What exists, and what does not

**Implemented:** parsing, grounding, evidence updates, graph corridors and
junctions with visibility and blocked edges, the five system variants, seeded
corruptions, protected instruction and split manifests, immutable paired logging
with replay equivalence, intervention budgets, temperature and isotonic
calibration, reliability and risk-coverage curves, SPL and route fidelity, paired
risk difference, contradiction recovery, hierarchical bootstrap, and the ROS 2
message, node, QoS and launch scaffolding.

**Not established:** any confirmatory claim. The completed development and
validation graph-world campaigns are diagnostics. Protected paraphrases and
splits remain protected. There is no result to report and none is implied.

## Why it is not public yet

Private while the study runs, opening at freeze — the same rule Research 1
followed. A benchmark whose protected paraphrases and splits are visible before
the analysis plan freezes is not a protected benchmark.
